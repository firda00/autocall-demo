# 📞 AutoCall Standalone Engine (Client-First Manager Bridge)

Автономный сервис умного автообзвона, выделенный из проекта **MetaSell**.

Готов к **демонстрации клиентам, инвесторам и руководству**:
- Работает **«из коробки» без внешних зависимостей** (Node.js >= 22).
- Имеет **интерактивную панель управления (Dashboard)** с живой анимацией соединения в реальном времени (Server-Sent Events).
- Включает **симулятор телефонии (Demo Mode)**, позволяющий наглядно показать все сценарии без затрат на связь.
- Поддерживает **боевое подключение к onlinePBX** при передаче API-ключей.

---

## 🎯 В чём ключевая ценность для бизнеса?

Большинство систем автообзвона соединяют клиента со случайным свободным оператором или заставляют клиента слушать музыку/гудки.

**AutoCall работает по технологии Client-First Manager Bridge:**
1. **Звонок начинается автоматически** из базы CRM/лидов.
2. Система ждёт **реального поднятия трубки клиентом**.
3. В ту же секунду происходит **моментальный мост на внутреннего менеджера**, закрепленного за этой сделкой (по его Extension ATS).
4. **Защита от потери клиентов**: если менеджер не вышел на смену — система **НЕ звонит** его клиентам, чтобы не бросать их на произвол судьбы.
5. **Защита от перегрузки**: один менеджер никогда не получит два звонка одновременно.
6. **Интеллектуальные повторы**: при "занято" или "не ответил" система планирует повтор с соблюдением суточных лимитов.
7. **Авто-эскалация в Telegram**: если за 3 попытки дозвониться не удалось, задача автоматически передаётся РОПу/менеджеру в Telegram для текстовой переписки.

## 🎬 Сценарии для эффектной демонстрации (Live Demo)

В демо-режиме настроены специальные тестовые номера для наглядности:
- **Номер, оканчивающийся на `77`** (например, `...3377`) — клиент **сразу берет трубку** (вы увидите зеленую анимацию моста и разговор с менеджером).
- **Номер, оканчивающийся на `99`** — клиент **занят** (система фиксирует статус и планирует повторный набор).
- **Номер, оканчивающийся на `00`** — клиент **не берет трубку** (после истечения таймера фиксируется недозвон).

### Что показать на встрече:
1. **Нажмите «На смену»** у менеджера (например, Мухлисы).
2. Нажмите **«Запустить обзвон»** — в прямом эфире появятся активные карточки с анимацией:
   - `📱 Набор клиента` ➔ `⚡ Клиент ответил` ➔ `🎧 Звонок на внутренний номер ATS` ➔ `🟢 Идет разговор`.
3. Покажите **Защиту смены**: снимите менеджера со смены («Снять со смены») — система мгновенно заморозит звонки его клиентам со статусом *"Менеджер не на смене"*.
4. Покажите **Эскалацию в Telegram**: при достижении лимита попыток карточка клиента перемещается в блок задач Telegram для переписки.

## ⚙️ Переключение на реальные звонки (onlinePBX)

Для перевода системы на боевые звонки создайте файл `.env` (по образцу `.env.example`):

```dotenv
PORT=4600
AUTOCALL_PROVIDER=onlinepbx
AUTOCALL_REAL_CALLS_CONFIRMED=true

ONLINEPBX_DOMAIN=yourcompany.onpbx.ru
ONLINEPBX_API_KEY=your_onlinepbx_api_key
ONLINEPBX_GATE_FROM=998711234567
ONLINEPBX_DISPLAY_NAME=U-STUDY
```

И запустите `npm start`. Звонки пойдут через реальную АТС с проверкой истории звонков по API onlinePBX.

## 🧪 Запуск автоматических тестов

Все критические правила бизнес-логики покрыты юнит-тестами (встроенный раннер Node.js):
```powershell
npm test
```
Тесты проверяют:
- Проверку рабочих часов (Ташкент UTC+5)
- Защиту от звонков при отсутствии менеджера на смене
- Правила маршрутизации Client-First
- Суточные лимиты и стоп-листы
